# Smart Waste Classification — Machine Learning Service

FastAPI inference service for classifying waste images into **organic**, **plastic**, and
**paper** using a MobileNetV2 transfer-learning model built with TensorFlow/Keras.

The service is stateless and is designed to be called internally by the NestJS backend. It
does not own a database and does not persist uploads.

## Result (actual measured test performance)

| Metric | Value |
|---|---:|
| Test accuracy | **91.30%** (63 / 69 correct) |
| Test images | 69 (23 per class) |
| Validation accuracy (best) | 100.00% (66 images) |
| Inference latency (CPU, batch 1) | ~63.6 ms end-to-end mean |
| Model artifact | `artifacts/waste_classifier.keras` (9.2 MB) |

These numbers come from `artifacts/evaluation/metrics.json`, generated by evaluating the
saved model on the held-out test split. The test set was not used for training or model
selection. See [Evaluation](#evaluation) for the full confusion matrix and classification
report.

> The test split is small (69 images), so 91.30% is an estimate with noticeable variance.
> The dataset can be regenerated deterministically with the command below.

## Requirements

- Python 3.12
- [uv](https://docs.astral.sh/uv/)
- Docker (optional, for deployment)
- Internet access for the first MobileNetV2 ImageNet weight download and dataset download

## Setup

### 1. Install uv

Linux / macOS:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Windows PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Verify:

```bash
uv --version
```

### 2. Install dependencies

```bash
uv sync
cp .env.example .env
```

`uv sync` downloads a compatible Python 3.12 interpreter if needed, creates `.venv`, and
installs runtime plus development dependencies. If you want to install Python 3.12
explicitly first:

```bash
uv python install 3.12
uv sync --python 3.12
```

## Dataset

The committed dataset contains **450 images**, 150 per class:

| Split | Organic | Plastic | Paper | Total |
|---|---:|---:|---:|---:|
| Training (70%) | 105 | 105 | 105 | 315 |
| Validation (15%) | 22 | 22 | 22 | 66 |
| Test (15%) | 23 | 23 | 23 | 69 |
| **Total** | **150** | **150** | **150** | **450** |

Source: [NeoAivara/Waste_Classification_data](https://huggingface.co/datasets/NeoAivara/Waste_Classification_data)
on Hugging Face. The source contains 12 garbage classes; this project selects `biological`
as `organic`, plus `plastic` and `paper`. License is documented as Apache-2.0 on the
dataset card. See [DATASET.md](DATASET.md) for provenance, license notes, class mapping,
deduplication, and splitting details.

Regenerate the dataset from scratch:

```bash
uv run python scripts/prepare_dataset.py --per-class 150 --seed 42
```

The script downloads the public parquet file, filters the three classes, removes
near-duplicate images per class using an average-hash check, and writes a deterministic
stratified 70/15/15 split plus `dataset/manifest.json`.

> `--force` replaces an existing populated `dataset/` directory. Use it intentionally.

## Training

```bash
uv run python -m waste_ml.training.train \
  --epochs 20 \
  --fine-tune-epochs 10 \
  --fine-tune-layers 30 \
  --batch-size 32 \
  --seed 42
```

Training runs in two phases:

1. **Feature extraction:** MobileNetV2 ImageNet backbone frozen; classification head
   (`GlobalAveragePooling2D → Dropout → Dense(softmax)`) trained with Adam at `1e-3`.
2. **Fine-tuning:** the last 30 backbone layers are unfrozen (BatchNorm stays frozen) and
   training continues at `1e-4`.

Callbacks: `ModelCheckpoint` (best validation accuracy), `EarlyStopping`, and
`ReduceLROnPlateau`. Training is reproducible with `--seed 42`; the environment and
hyperparameters are written to `artifacts/model_metadata.json`.

Recorded run:

- Training duration: ~200 seconds on CPU
- Phase 1 stopped after 12 epochs; best validation accuracy 100% at epoch 7
- Fine-tuning stopped after 7 epochs; best validation accuracy 100% at epoch 14
- Training environment: Python 3.12.16, TensorFlow 2.21.0, CPU only

## Running the API

```bash
uv run uvicorn waste_ml.api.main:app --host 0.0.0.0 --port 8000
```

Open:

- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`
- OpenAPI schema: `http://localhost:8000/openapi.json`

The model is loaded exactly once during FastAPI startup. If the artifact or metadata
cannot be loaded, startup fails with a clear error instead of serving a broken service.

### Endpoints

| Method | Path | Description |
|---|---|---|
| GET | `/health` | Public health check |
| GET | `/api/v1/health` | Versioned health check |
| GET | `/api/v1/model/info` | Model metadata |
| POST | `/api/v1/predict` | Classify a waste image |

### Prediction example

```bash
curl -X POST http://localhost:8000/api/v1/predict \
  -F "file=@dataset/test/plastic/plastic_0000.jpg;type=image/jpeg"
```

```json
{
  "predicted_class": "plastic",
  "confidence": 0.9997380375862122,
  "probabilities": {
    "organic": 0.00005783060260000639,
    "plastic": 0.9997380375862122,
    "paper": 0.0002041414991253987
  },
  "model_version": "1.0.0"
}
```

Upload rules:

- Formats: JPEG/JPG, PNG, and WebP when the installed Pillow decoder supports it.
- Maximum size: 5 MB (`MAX_UPLOAD_SIZE_MB`).
- Validation uses the decoded image format, not only the client filename or MIME type.
- Uploads are processed in memory and are not stored permanently.

Error responses use a consistent `{"detail": ...}` shape:

| Status | Condition |
|---|---|
| 400 | Invalid or unreadable image |
| 413 | File exceeds the maximum size |
| 415 | Decoded image format is unsupported |
| 422 | Request validation error (for example, missing file) |
| 500 | Internal inference error |

`confidence` is the model's probability for the predicted class. It is not the model's
overall accuracy.

```bash
docker build -t waste-ml .
docker run --rm -p 8000:8000 waste-ml
```

The service can also be reached only through an internal Docker network in deployment.

## Integration with NestJS

Example backend configuration:

```env
ML_SERVICE_URL=http://ml:8000
ML_SERVICE_TIMEOUT_MS=15000
```

NestJS forwards the uploaded image to `POST /api/v1/predict` as `multipart/form-data`
using the field name `file`, then stores the prediction in PostgreSQL. NestJS owns
authentication, report persistence, report status, and user-facing error handling.

A 15-second timeout is an initial value; adjust it after measuring production inference
latency.

| `APP_NAME` | `Waste ML Service` | Service name |

| `APP_HOST` | `0.0.0.0` | Bind host |

| `MODEL_METADATA_PATH` | `artifacts/model_metadata.json` | Model metadata path |
| `MAX_UPLOAD_SIZE_MB` | `5` | Upload size limit |

Relative paths are resolved from the service root. Do not commit secrets or credentials.

## Model metadata

`artifacts/model_metadata.json` contains the model name, version, framework, architecture,
input shape, class mapping, dataset reference and counts, training date, hyperparameters,
environment, best validation accuracy, and final evaluation metrics.

## Limitations

- The dataset is small and was sampled from a single public source; results may not
  generalize to all real-world waste images.
- 5 plastic test images were misclassified as paper.
- The model expects the entire image to contain the waste object; no object detection or
  cropping is performed.
- A confidence score is not a calibrated probability of correctness.
- The service performs no authentication; deploy it on a private network and let NestJS
  expose the public API.
