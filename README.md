# WasteWaste ML — Machine Learning Service

WasteWaste ML is a FastAPI inference service for classifying waste images into **organic**,
**plastic**, and **paper** using a MobileNetV2 transfer-learning model built with
TensorFlow/Keras.

The service is stateless and is designed to be called internally by the NestJS backend. It
does not own a database and does not persist uploads.

## Result (actual measured test performance)

| Metric | Value |
|---|---:|
| Test accuracy | **95.63%** (175 / 183 correct) |
| Test images | 183 (61 per class): 69 clean photos (95.65%) + 114 field-style photos (95.61%) |
| Validation accuracy (best) | 97.74% (177 images) |
| Inference latency (CPU, batch 1) | ~57.4 ms end-to-end mean |
| Model artifact | `artifacts/waste_classifier.keras` (9.2 MB) |

These numbers come from `artifacts/evaluation/metrics.json`, generated by evaluating the
saved model on the held-out test split. The test set was not used for training or model
selection. See [Evaluation](#evaluation) for the full confusion matrix and classification
report.

> The test split is small (183 images), so 95.63% is an estimate with noticeable variance.
> RealWaste photos come from one facility and many are near-identical frames, so the
> field-style figure may be optimistic. Version 1.0.0 (clean photos only) scored 79.8% on
> those same field-style test photos before retraining, which is why the second source
> was added. The dataset can be regenerated deterministically with the command below.

## Requirements

- Python 3.12
- [uv](https://docs.astral.sh/uv/)
- Docker (optional, for deployment)
- Internet access for the first MobileNetV2 ImageNet weight download and dataset download

## Setup

### 1. Install uv

Linux / macOS:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Windows PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Verify:

```bash
uv --version
```

### 2. Install dependencies

```bash
uv sync
cp .env.example .env
```

`uv sync` downloads a compatible Python 3.12 interpreter if needed, creates `.venv`, and
installs runtime plus development dependencies. If you want to install Python 3.12
explicitly first:

```bash
uv python install 3.12
uv sync --python 3.12
```

## Dataset

The committed dataset contains **1,200 images**, 400 per class, from two sources:

| Split | Organic | Plastic | Paper | Total |
|---|---:|---:|---:|---:|
| Training (70%) | 280 | 280 | 280 | 840 |
| Validation (15%) | 59 | 59 | 59 | 177 |
| Test (15%) | 61 | 61 | 61 | 183 |
| **Total** | **400** | **400** | **400** | **1,200** |

Each class holds 150 clean photos from
[NeoAivara/Waste_Classification_data](https://huggingface.co/datasets/NeoAivara/Waste_Classification_data)
(Apache-2.0; `biological` as `organic`, plus `plastic` and `paper`) and 250 field-style photos from
[RealWaste](https://huggingface.co/datasets/shahzaibvohra/realwaste) (CC BY 4.0; `Food Organics`
and `Vegetation` as `organic`, `Plastic`, `Paper` and `Cardboard` as `paper`). Both sources are
split 70/15/15 separately, so every split contains both photo styles. See
[DATASET.md](DATASET.md) for provenance, license notes, attribution, class mapping,
deduplication, and splitting details.

Regenerate the dataset from scratch:

```bash
uv run python scripts/prepare_dataset.py --per-class 150 --realwaste-per-class 250 --seed 42 --force
```

The script downloads the public parquet file, filters the three classes, removes
near-duplicate images per class using an average-hash check, and writes a deterministic
stratified 70/15/15 split plus `dataset/manifest.json`.

> `--force` replaces an existing populated `dataset/` directory. Use it intentionally.

## Training

```bash
uv run python -m waste_ml.training.train \
  --epochs 20 \
  --fine-tune-epochs 10 \
  --fine-tune-layers 30 \
  --batch-size 32 \
  --seed 42
```

Training runs in two phases:

1. **Feature extraction:** MobileNetV2 ImageNet backbone frozen; classification head
   (`GlobalAveragePooling2D → Dropout → Dense(softmax)`) trained with Adam at `1e-3`.
2. **Fine-tuning:** the last 30 backbone layers are unfrozen (BatchNorm stays frozen) and
   training continues at `1e-4`.

Callbacks: `ModelCheckpoint` (best validation accuracy), `EarlyStopping`, and
`ReduceLROnPlateau`. Training is reproducible with `--seed 42`; the environment and
hyperparameters are written to `artifacts/model_metadata.json`.

Recorded run:

- Training duration: ~421 seconds on CPU (model 1.1.0)
- Phase 1 stopped after 9 epochs; fine-tuning ran 10 epochs
- Best validation accuracy 97.74% at epoch 14
- Training environment: Python 3.12.16, TensorFlow 2.21.0, CPU only

## Running the API

```bash
uv run uvicorn waste_ml.api.main:app --host 0.0.0.0 --port 8000
```

Open:

- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`
- OpenAPI schema: `http://localhost:8000/openapi.json`

These are served only when `APP_ENV` is not `production`. In production, `/api/v1/*` also
requires the `X-Internal-Token` header (see [Internal authentication and limits](#internal-authentication-and-limits)).

The model is loaded exactly once during FastAPI startup. If the artifact or metadata
cannot be loaded, startup fails with a clear error instead of serving a broken service.

### Endpoints

| Method | Path | Description |
|---|---|---|
| GET | `/health` | Public health check |
| GET | `/api/v1/health` | Versioned health check |
| GET | `/api/v1/model/info` | Model metadata |
| POST | `/api/v1/predict` | Classify a waste image |

### Prediction example

```bash
curl -X POST http://localhost:8000/api/v1/predict \
  -H "X-Internal-Token: $INTERNAL_TOKEN" \
  -F "file=@dataset/test/plastic/plastic_0000.jpg;type=image/jpeg"
```

The header is only checked when `INTERNAL_TOKEN` is set (required when `APP_ENV=production`).

```json
{
  "predicted_class": "plastic",
  "confidence": 0.9997380375862122,
  "probabilities": {
    "organic": 0.00005783060260000639,
    "plastic": 0.9997380375862122,
    "paper": 0.0002041414991253987
  },
  "model_version": "1.0.0"
}
```

Upload rules:

- Formats: JPEG/JPG, PNG, and WebP when the installed Pillow decoder supports it.
- Maximum size: 5 MB (`MAX_UPLOAD_SIZE_MB`); decoded images above 25 megapixels are rejected with 400.
- Validation uses the decoded image format, not only the client filename or MIME type.
- Uploads are processed in memory and are not stored permanently.

Error responses use a consistent `{"detail": ...}` shape:

| Status | Condition |
|---|---|
| 400 | Invalid or unreadable image |
| 413 | File exceeds the maximum size |
| 415 | Decoded image format is unsupported |
| 422 | Request validation error (for example, missing file) |
| 500 | Internal inference error |

`confidence` is the model's probability for the predicted class. It is not the model's
overall accuracy.

## Docker

The image includes the trained model artifact and runs Uvicorn:

```bash
docker build -t wastewaste-ml .
docker run --rm -p 8000:8000 -e INTERNAL_TOKEN=change-me-to-a-long-random-string wastewaste-ml
```

The image defaults to `APP_ENV=production`, so it refuses to start without `INTERNAL_TOKEN`.

The service can also be reached only through an internal Docker network in deployment.

## Integration with NestJS

Example backend configuration:

```env
ML_SERVICE_URL=http://ml:8000
ML_SERVICE_TOKEN=<same value as the ML INTERNAL_TOKEN>
ML_SERVICE_TIMEOUT_MS=15000
```

NestJS forwards the uploaded image to `POST /api/v1/predict` as `multipart/form-data`
using the field name `file`, then stores the prediction in PostgreSQL. NestJS owns
authentication, report persistence, report status, and user-facing error handling.

A 15-second timeout is an initial value; adjust it after measuring production inference
latency.

## Model metadata

`artifacts/model_metadata.json` contains the model name, version, framework, architecture,
input shape, class mapping, dataset reference and counts, training date, hyperparameters,
environment, best validation accuracy, and final evaluation metrics.

## Limitations

- The dataset is small (1,200 images, two public sources); results may not generalize to
  all real-world waste images. In informal checks with phone photos, a pile of mixed paper
  was still classified as organic and unrelated photos (a poster, people) were forced into
  one of the three classes: the model has no "not waste" class.
- 4 plastic test images were misclassified as paper and 2 paper images as organic.
- The model expects the entire image to contain the waste object; no object detection or
  cropping is performed.
- A confidence score is not a calibrated probability of correctness.
- The service performs no authentication; deploy it on a private network and let NestJS
  expose the public API.

## Internal authentication and limits

- `INTERNAL_TOKEN`: shared secret the NestJS backend sends as `X-Internal-Token` (backend env `ML_SERVICE_TOKEN`). `/api/v1/*` returns 401 without it; `/health` stays open. Required when `APP_ENV=production` (the service refuses to start otherwise). Keep the service on a private network; never publish port 8000.
- Images above 25 megapixels (decoded size, checked from the header) are rejected with 400, and decompression-bomb errors also return 400.
- `MAX_CONCURRENT_PREDICTIONS` (default 4) bounds simultaneous decode+inference jobs; set a container memory limit as well.
- `/docs`, `/redoc` and `/openapi.json` are disabled when `APP_ENV=production`; the Docker image defaults to production and runs as a non-root user.
